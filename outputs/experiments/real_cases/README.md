# A 模块真实样本实验报告

实验日期：2026-11-16

## 1. 实验目的

本实验验证成员 A 负责的预处理与候选裁剪模块是否满足以下要求：批量读取图片、校正 EXIF 方向、提取元信息、保护原图、为每张正常图片生成不超过 7 个合法候选，并能够处理横图、竖图、超长图、损坏图片和不支持格式。同时重点检查“人脸优先裁剪”是否会把建筑或动物纹理错误识别为人脸。

## 2. 测试数据

共 13 个文件，其中 11 个为应成功处理的图片，2 个为应拒绝的异常文件：

- 横图、竖图、5:1 超宽图、超长竖图；
- 两张含真人脸的宇航员图片；
- 埃菲尔铁塔、火箭、猫、狗、静物及灰度图片；
- EXIF Orientation=6 的方向测试图；
- 截断损坏的 JPEG；
- 当前系统不支持的 BMP。

文件清单及期望状态见 `data/sample/real_cases/cases_manifest.csv`，图片来源与许可见 `data/sample/real_cases/SOURCES.md`。前后两轮实验使用同一组输入图片和同一套候选生成流程，只替换人脸检测器。

## 3. 固定的预处理与候选方法

1. 使用 OpenCV 解码并验证图片，使用 Pillow 读取 EXIF 和原始元信息。
2. 使用 `ImageOps.exif_transpose` 校正方向，将结果另存为无损 PNG，不覆盖原文件。
3. 候选包括原图、常见比例中心裁剪、人脸感知裁剪和显著性偏移裁剪。
4. 横图比例为 `1:1、4:3、16:9`，竖图比例为 `1:1、3:4、9:16`。
5. 使用 Spectral Residual 显著性检测；不可用时回退到 Sobel 边缘能量。
6. 候选必须位于原图边界内，最小尺寸为 64 px；IoU 不低于 0.98 的近重复框只保留一个，最终最多返回 7 个。
7. 人脸和显著性检测在缩小图上运行，随后将坐标映射回原始分辨率；裁剪文件仍按原始分辨率保存。

## 4. 第一轮：Haar/LBP 基线实验

第一版人脸池优先使用 OpenCV 的 Haar frontal-face 级联，Haar 文件不可用时使用项目内的 LBP 级联。主要参数为：

- `scaleFactor=1.1`：每层图像金字塔缩小约 10%；
- `minNeighbors=5`：候选框至少需要 5 个邻域支持；
- 最小人脸尺寸约为 32 px；
- 检测最长边限制为 1600 px；
- 人脸联合框向外扩张 2 倍后生成取景候选。

### 4.1 第一轮发现的问题

最初的级联检测把埃菲尔铁塔的重复结构误报为人脸，其级联 `levelWeight` 约为 2.085。加入 `levelWeight >= 3.0` 的过滤后，铁塔误检被排除，但狗图仍出现两个较高响应，约为 6.679 和 3.534，并被错误放入 `face` 候选池。

这说明仅继续提高级联阈值并不能可靠解决问题：阈值过低会保留建筑和动物误检，阈值过高又可能漏掉真实人脸。狗图产生了可用裁剪，但“裁剪可用”不等于“人脸分类正确”，因此不能把它作为人脸检测成功来报告。

### 4.2 过滤后的基线结果

- 预处理成功：11/13；另外 2 个异常文件按预期拒绝；
- 按样本期望状态判断的正确率：100%；
- 正常图片裁剪成功率：100%；
- 平均预处理耗时：154.372 ms/文件；
- 平均裁剪生成耗时：872.748 ms/成功图片；
- 平均返回候选数：6.636 个/图片；
- 总体候选有效率：90.361%；
- 真人脸能够进入人脸池，埃菲尔铁塔经阈值过滤后不再进入，但狗仍被误标为人脸。

## 5. 为什么改用 YuNet

Haar/LBP 使用手工设计的亮暗和纹理特征，通过级联分类器逐层排除窗口，优点是轻量，但对真实人脸与相似局部纹理的区分能力有限。YuNet 是 OpenCV Zoo 提供的轻量神经网络人脸检测模型，专门在大量人脸样本上训练，能够同时利用更完整的脸部结构信息，并输出 0–1 置信度，因此更适合当前“真人脸进入人脸池，建筑和动物不冒充人脸”的目标。

最终实现以 `face_detection_yunet_2023mar.onnx` 为主模型。Haar/LBP 只在 YuNet 模型或 OpenCV `FaceDetectorYN` 接口无法加载时作为兼容后备；如果 YuNet 正常运行并返回 0 张脸，不会再调用级联模型强行产生人脸候选。

YuNet 参数设置如下：

- `score_threshold=0.90`：过滤低于 0.90 的检测框；该数值是模型分数门槛，不代表系统准确率为 90%；
- `nms_threshold=0.30`：两个框重叠 IoU 超过门槛时，非极大值抑制保留分数更高的框；
- `top_k=5000`：NMS 前最多保留 5000 个预测框；
- 检测图最长边为 1600 px；
- 最终人脸取景框仍向外扩张 2 倍，以保留人物周围环境。

模型来源、SHA-256 和许可证记录在 `models/face/README.md`。

## 6. 第二轮：YuNet 对照实验

替换检测器后，使用完全相同的 13 个文件重新运行 `scripts/run_a_experiment.py`。逐图片 CSV 额外记录 `face_detector`、`face_detection_count`、`face_score_threshold` 和 `face_nms_threshold`，用于确认本轮确实执行了 YuNet，而不是沿用旧结果。

### 6.1 关键样本结果

| 样本 | Haar/LBP 过滤后 | YuNet 最终结果 | 结论 |
|---|---|---|---|
| 宇航员真人脸 | 检测到人脸 | 检测到人脸，`05_face_astronaut` 为 1 张 | 保留真人脸能力 |

| 猫、静物、风景 | 主要由显著性处理 | 0 张人脸，由显著性处理 | 候选生成流程保持完整 |

## 8. 结论与限制

YuNet 在保留真人脸候选的同时，解决了当前真实样本中狗被错误放入人脸池的问题；埃菲尔铁塔也保持 0 人脸结果。与 Haar/LBP 基线相比，总体候选有效率提高 2.232 个百分点，单次实验中的平均裁剪耗时也有所下降。因此最终版本采用 YuNet 作为人脸主检测器是有实验依据的，而不是仅为了通过特定样本。

当前人脸模型只负责真人脸，不宣称能够检测狗脸或猫脸。动物、建筑和静物由显著性算法产生主体候选。现有结论基于 13 个功能与回归样本，若要报告通用人脸检测准确率，还需要建立包含更多正负例并带人脸框标注的独立测试集，统计 precision、recall 和 IoU。
